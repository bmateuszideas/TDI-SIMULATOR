# Workflow: Local Dev → CI → Release

This document defines the expected engineering workflow for the Virtual TDI simulator.

## 1) Local development

### Setup
```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### Run
```bash
python -m virtual_tdi --help
python -m virtual_tdi --mode full --rpm 1500 --fuel diesel --fuel-mg 20 --out out
```

### Tests
```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

## 2) Continuous Integration (CI)

CI runs on GitHub Actions for Python 3.12:
- installs dependencies
- runs unit tests
- fails the build if tests fail

The CI configuration lives in `.github/workflows/ci.yml`.

## 3) Release process

1. Ensure `main` is green in CI.
2. Decide release version (e.g., `v0.2.0`).
3. Tag and push:
   ```bash
   git checkout main
   git pull
   git tag -a v0.2.0 -m "Release v0.2.0"
   git push origin v0.2.0
   ```
4. (Optional) Create GitHub Release with notes and attach artifacts.

## 4) Quality gates

Minimum requirements before merge:
- `python -m unittest discover -s tests -p "test_*.py" -v` passes
- `python -m virtual_tdi --help` works
- `python -c "import virtual_tdi"` works

## 5) Artifacts

Artifacts generated by local runs (e.g., `out/`, `out_*`, `*.png`, `*.csv`) should not be committed.
Use `.gitignore` to keep them out of the repository.
